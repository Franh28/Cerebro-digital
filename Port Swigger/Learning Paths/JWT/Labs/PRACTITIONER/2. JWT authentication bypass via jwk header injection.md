### Paso 1: Capturar tu JWT normal y confirmar que /admin está bloqueado

1. Inicia sesión en el lab con tu cuenta normal (`wiener`)
2. Ve a **Proxy** → **HTTP history** en Burp
3. Busca la petición `GET /my-account` que ocurre justo después del login
4. Click derecho → **Send to Repeater**
5. En **Repeater**, cambia la ruta de `/my-account` a `/admin`
6. Click **Send**
7. Observa que la respuesta es un error de acceso (403 o similar) — confirmando que con tu token normal (`"sub":"wiener"`) no puedes entrar

---

### Paso 2: Crear tu propio par de claves RSA en Burp

Aquí generas tu propio juego de claves (pública + privada), que usarás para firmar el token falso.

1. Ve a la pestaña **JWT Editor Keys** (en la barra superior de Burp, añadida por la extensión)
2. Click en **New RSA Key**
3. Se abre un diálogo
4. Click en **Generate** → Burp crea automáticamente un par de claves RSA nuevo (pública y privada), aunque tú solo verás los datos técnicos en formato JWK
5. Click en **OK** para guardar esa clave

Ahora tienes en Burp un par de claves RSA propio, completamente independiente de las claves reales del servidor.

---

### Paso 3: Modificar el payload del token

1. Vuelve a la petición `GET /admin` en **Repeater** (la misma de antes)
2. Busca la pestaña **JSON Web Token** (al lado de Pretty/Raw/Hex)
3. En el **payload**, busca:

json

```json
   "sub": "wiener"
```

4. Cámbialo a:

json

```json
   "sub": "administrator"
```

Igual que en el ataque anterior, esto dice "soy el administrador" — pero ahora, en vez de firmar con una clave secreta compartida, vamos a usar el truco del `jwk`.

---

### Paso 4: El ataque — "Embedded JWK"

Esta es la parte clave que diferencia este ataque del anterior.

1. En la parte inferior de la pestaña **JSON Web Token**, busca el botón **Attack**
2. Click ahí → se despliega un menú → selecciona **Embedded JWK**
3. Te pedirá seleccionar qué clave usar → elige la clave RSA que generaste en el Paso 2
4. Click **OK**

**¿Qué hace Burp automáticamente al hacer esto?**

- Firma el token (con el payload modificado a `administrator`) usando TU clave privada RSA
- Añade un nuevo campo `jwk` dentro del **header** del JWT, conteniendo TU clave pública
- El header queda más o menos así:

json

```json
   {
     "alg": "RS256",
     "jwk": {
       "kty": "RSA",
       "n": "...",
       "e": "AQAB",
       ...
     }
   }
```

---

### Paso 5: Verificar el cambio en el header

1. Antes de enviar, échale un vistazo al header del token (arriba en esa misma pestaña)
2. Confirma que ahora aparece el parámetro `jwk` con tu clave pública dentro — esto es la "prueba" falsa que le vas a entregar al servidor para que la use en la verificación

---

### Paso 6: Enviar la petición falsificada

1. Asegúrate de que la ruta sigue siendo `/admin`
2. Click **Send**
3. Si el servidor es vulnerable (como en este lab), usará la clave pública que tú le diste en `jwk` para verificar la firma
4. Como tú firmaste con la clave privada correspondiente, la verificación "cuadra" perfectamente
5. Deberías ver en la respuesta el **panel de administración** (código 200)
