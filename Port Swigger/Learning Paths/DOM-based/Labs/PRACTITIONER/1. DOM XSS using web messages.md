En la página base hay un:
```
<script>
	window.addEventListener('message', function(e) {
		document.getElementById('ads').innerHTML = e.data;
	})
</script>
```

Podemos aprovechar el listener y mandar un mensaje.
Como tenemos que forzar un print hacemos el siguiente iframe:
```
<iframe src="https://0ac600b504d0764983593219005e00bc.web-security-academy.net/" onload=" this.contentWindow.postMessage('<img src=quefalle onerror=print()>','*')">
```


**1. Antes de la coma:** `'<img src=1 onerror=print()>'`  
Es el **dato/mensaje** que se envía al iframe. En este caso es un string con HTML malicioso (la carga XSS), que el script del iframe luego mete directamente en `innerHTML`, provocando que el navegador intente cargar la imagen rota y, al fallar (`onerror`), ejecute `print()`.

**2. Después de la coma:** `'*'`  
Es el segundo parámetro de `postMessage`, llamado **`targetOrigin`**. Sirve para decirle al navegador: "solo entrega este mensaje si la ventana destino tiene exactamente este origen (dominio/protocolo/puerto)".

- Si pusieras algo como `'https://ejemplo.com'`, el mensaje solo se entregaría si el iframe está actualmente cargado desde ese origen exacto.
- El asterisco `*` significa **"cualquier origen"** — no hay restricción, el mensaje se envía pase lo que pase.

**Por qué importa en este reto:**  
Usar `'*'` como `targetOrigin` es justo la mala práctica que este laboratorio de PortSwigger quiere ilustrar. Si el sitio que carga el iframe usa `'*'`, no está verificando a quién le envía el mensaje, y si el sitio que _recibe_ el mensaje (el que tiene el `window.addEventListener`) tampoco verifica `e.origin` antes de usar `e.data`, cualquier página puede inyectar contenido arbitrario (incluido JS vía `onerror`, como ves aquí) en ese iframe — de ahí la vulnerabilidad XSS basada en `postMessage`.
