El Back to log dentro de los posts tiene el siguiente enlace:
```
<a href="#" onclick="returnUrl = /url=(https?:\/\/.+)/.exec(location); location.href = returnUrl ? returnUrl[1] : &quot;/&quot;">Back to Blog</a>
```

Vamos a desmontarlo pieza a pieza.

**1. La expresión regular:**

```js
/url=(https?:\/\/.+)/
```

- `url=` → busca literalmente el texto `url=`
- `https?:` → `http:` o `https:` (la `s` es opcional)
- `\/\/` → las dos barras `//` (escapadas porque el regex está delimitado por `/`)
- `.+` → uno o más caracteres cualesquiera, hasta el final
- Los paréntesis `( ... )` crean un **grupo de captura**: la parte que nos interesa extraer

**2. `.exec(location)`**  
`location` (el objeto, no un string) se convierte automáticamente a texto, que es la URL completa de la página actual, por ejemplo:

```
https://TU-LAB-ID.web-security-academy.net/post?postId=4&url=https://ejemplo.com/
```

`.exec()` ejecuta el regex contra esa cadena y, si encuentra coincidencia, devuelve un array donde:

- `returnUrl[0]` = toda la coincidencia completa
- `returnUrl[1]` = lo capturado por el primer grupo `(...)`, es decir, **todo lo que viene después de `url=`**

**3. La redirección:**

```js
if (returnUrl) location.href = returnUrl[1];
else location.href = "/";
```

Si el regex encontró algo, el navegador redirige a `returnUrl[1]` (el valor del parámetro `url`). Si no, va a la home (`/`).

Esto podemos usarlo en una situación potencial para mandar a una víctima a nuestra web, en este caso el exploit server:
```
https://TU-LAB-ID.web-security-academy.net/post?postId=4&url=https://TU-EXPLOIT-SERVER-ID.exploit-server.net/
```
